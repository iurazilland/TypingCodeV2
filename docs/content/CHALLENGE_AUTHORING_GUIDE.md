# 🏆 챌린지 레벨 작성 가이드 (Challenge Authoring Guide)

이 문서는 **TypingCode**의 챌린지 레벨(Level 10, 15, 20 등)을 설계하고 작성할 때 준수해야 하는 표준 규칙을 정의합니다. 챌린지 모드는 학습자가 배운 내용을 종합적으로 복습하고 응용하는 단계이므로, 일관된 사용자 경험과 교육적 효과를 보장해야 합니다.

---

## 1. 문항 구성 원칙 (3-3-2-2 법칙)

각 챌린지 레벨은 총 10개의 문항으로 구성하며, 난이도 조절과 학습 목표 달성을 위해 다음 배치를 권장합니다.

| 유형 | 문항 수 | 설명 | 가이드 서두 (필수) |
| :--- | :---: | :--- | :--- |
| **Blank (빈칸)** | 3 | 코드의 핵심 키워드나 연산자를 빈칸으로 비움 | **빈칸을 채워** ... |
| **Line (한 줄)** | 3 | 비어있는 한 줄의 코드를 완성 (주로 변수 선언/할당) | **한 줄의 코드로** ... |
| **Fix (수정)** | 2 | 문법 오류나 논리적 오류가 있는 코드를 수정 | **틀린 곳을 수정하여** ... |
| **Full Code (전체)** | 2 | 입출력 조건에 맞는 전체 로직을 작성 (Q9, Q10) | **코드를 작성하여** ... |

---

## 2. 가이드 문구 표준화 (Standard Guide Prefixes)

학습자가 문제 유형을 즉각적으로 파악할 수 있도록, `Guide_KO`의 시작 부분은 반드시 아래의 표준 문구를 사용해야 합니다.

*   **빈칸 채우기**: `빈칸을 채워 [목표]를 수행하세요.`
*   **한 줄 작성**: `한 줄의 코드로 [목표]를 수행하세요.`
*   **오류 수정**: `틀린 곳을 수정하여 [오류 해결 및 목표]를 달성하세요.`
*   **전체 작성**: `코드를 작성하여 [복합 목표]를 수행하는 프로그램을 만드세요.`

---

## 3. 빈칸(`^`) 시각적 힌트 규칙

빈칸 문제(`Blank`)에서 사용하는 캐럿 기호(`^`)의 개수는 **정답의 글자 수와 일치**시켜야 합니다. 이는 학습자에게 직관적인 힌트를 제공하여 문제의 난이도를 조절하고 정답 유추를 돕습니다.

*   **연산자 (1글자)**: `num ^ 2 == 0` (정답: `%`)
*   **산술 연산 (2글자)**: `days ^^ 7` (정답: `//`)
*   **논리 연산 (3글자)**: `score >= 0 ^^^ score <= 100` (정답: `and`)
*   **함수명 (3글자 이상)**: `count = ^^^(nums)` (정답: `len`)

---

## 4. 교육적 가이드 설계 (Insight-First Pedagogy)

챌린지는 정답을 알려주는 곳이 아니라, **스스로 생각하게 하는 곳**입니다.

1.  **정답 직접 노출 금지**: 가이드나 힌트에서 정답 코드를 직접 언급하지 않습니다. (예: "`append`를 사용하세요" (X) -> "리스트 끝에 항목을 추가하는 메서드를 사용하세요" (O))
2.  **원리 중심 설명**: "무엇을" 해야 하는지보다 "어떤 원리"를 활용해야 하는지 설명합니다.
3.  **힌트 라벨 금지**: 가이드 텍스트 내에 "힌트:"라는 머리말을 사용하지 않고 자연스럽게 설명에 녹여냅니다.
4.  **역동적 힌트**: 메서드 사용이 필수적인 경우, 문제의 배경 설명으로 메서드의 역할을 슬쩍 언급해 줍니다.

---

## 5. 테스트 케이스 규격 (Test Case Standards)

챌린지의 완성도는 풍부한 테스트 케이스에서 나옵니다.

1.  **최소 수량**: `input()`이 포함된 문항은 반드시 **10개 이상의 테스트 케이스**를 포함해야 합니다.
2.  **경계값 테스트**: `0`, `-1`, 빈 문자열, 매우 큰 수 등 예외적인 상황을 반드시 테스트 케이스에 포함합니다.
3.  **형식**: 반드시 `Input:`, `Output:` 키워드를 사용하며, 입력이 없는 경우 `Input: (None)`으로 표기합니다.
